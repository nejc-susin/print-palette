# Print Palette

Static filament picker. Friends choose up to eight colors and share the ordered selection by URL. It is not a shop; do not add prices, checkout, accounts, reservations, or payments.

## Product rules

- Supports Bambu Lab PLA Basic, PLA Matte, PETG HF, and PETG Translucent.
- Show available colors by default; the full catalog clearly marks availability.
- Never mute the swatch itself. Unavailable cards may mute only their information panel.
- Show the material line (e.g. PLA Matte, PETG HF), official color name, hex swatch, and five-digit Bambu color ID. Translucent swatches sit on a checkerboard.
- My Picks is a flat, reorderable list of up to eight unique colors.
- Shared links use `#v=1&p=10100,10200`; order is preserved.
- Ignore malformed, duplicate, and unknown IDs safely. No pre-release link compatibility is required.
- Each card shows an Opened, Sealed, or Not on hand pill. The Filter control has an opened-only view. My Picks shows a short tip that opened spools are ideal for prints under about 100 g.
- A collapsed "Which material should I pick?" guide under the filters explains each material in plain language for non-printers; each entry can apply the Material filter. Keep its claims conservative (no food-safety promises).
- Public data exposes only binary availability and binary opened state per color—never quantity, price, or purchase data.

## Data

- `public/data/catalog.json`: complete public PLA Basic, PLA Matte, PETG HF, and PETG Translucent catalog.
- `public/data/inventory.json`: currently available Bambu IDs in `availableColorIds`; the opened subset in `openedColorIds`. Generated by `npm run sync` from the spreadsheet's published `site` tab; see README.
- Keep private spreadsheet data out of the site and production build.

## Implementation

- Vanilla TypeScript, Vite, semantic HTML, and custom CSS.
- No framework, database, backend, authentication, analytics, or runtime third-party assets.
- Production output is the static `dist/` directory for Nginx.

Before finishing changes, run `npm test` and `npm run build`. Check selection restoration and relevant mobile/desktop states when UI behavior changes.
